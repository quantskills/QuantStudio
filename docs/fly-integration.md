# AI 交易员接入约定

AI 交易员位于「比赛」内的独立工作台，可选择 QS 已配置的大模型或原有神经引擎。神经实现源自 `songshuquant/ssquant-fly-agent` 的 `codex/fly-autonomous-v2`；内部 `fly` 路径保留兼容。生活页使用浏览器中的数字生命花园，不需要 Blender，也不依赖交易盈亏驱动。

交易复用 PandaAI 比赛 CLI，历史行情复用 PandaData。JEV 与 AI 交易员都支持逐笔确认或本轮授权后的自动下单；两者不同时控制同一账户。每个合约分别决策，宿主核对账户、行情、持仓与额度，再预演、生成计划并按所选方式执行。同合约有活动委托时等待回执，提交结果不明时先核对，不重发。

Python 控制器运行在独立进程，神经模式另需神经 Python 与 MaleCNS。账户凭据和 CLI 执行留在宿主；模型调用复用 QS 已验证配置。模块随应用分发，首次准备环境将依赖下载到用户目录并校验。

关闭页面不停止宿主中的后台运行；退出 Host 时保存运行状态。AI 交易员只恢复同一运行编号的有效自动授权，手动暂停保持暂停，不重放旧信号；JEV 重启后保持停止。数字生命花园的存档与交易运行独立。

验证需分别记录环境准备、神经运行、页面交互、状态恢复和交易链路；模拟 CLI 测试不能替代真实柜台成交验证。

## QS 大模型交易模式

入口为「比赛 → AI 交易员 → 交易设置 → 决策引擎」。可选择大模型交易员或原有神经交易员，旧配置仍默认使用神经模型，不会自动切换。大模型直接复用 QS 已验证的服务与模型，输入几句交易要求即可；单合约手数（默认 1 手）和每日调用上限（0 表示不限）在折叠菜单中调整。运行中先暂停再修改，保存配置不会擅自恢复已经暂停的交易。

大模型模式只需基础 Python 控制器，无需 MaleCNS 或 Blender。行情继续复用本地完整 500 根窗口，每个合约每个完整周期分析一次最近 60 根 K 线、实时快照、持仓与可用手数，最多 3 个并发请求。输出格式为合约、WAIT/LONG/SHORT/CLOSE、目标净持仓和理由；由本地校验器检查格式与目标范围，再进入 CLI 计划与执行链路。每日调用次数独立记为 trade_model，不占用生活辅助额度；页面显示各合约的分析中、失败、决策理由与执行回执。

LLM 输出保存为 llm-trade-1，保留最初行情时间，最长 90 秒有效；实际下单仍再次查询新鲜报价和当前持仓。模型、交易要求、手数或运行编号变化时，未完成的旧结果直接丢弃。模型超时、无效响应或额度耗尽不会切换到神经决策，不会据此下单。连续确认、开仓冷却与原有额度核对继续生效；神经分差过滤和神经学习不应用到大模型决策，不伪造神经分数或学习记录。

升级需要重启后台进程。旧后台运行时，新前端会禁用大模型选项并提示重启；当前正在自动交易时应由用户先暂停，更新不会替用户切换模型或重新启动交易。

## 配置与使用

1. 从「比赛 → AI 交易员」进入独立工作台，在设置中选择决策引擎。大模型模式复用 QS 已验证模型与基础控制器；神经模式使用一键准备的专用 Python 与 MaleCNS。准备进度、错误和重试均在页面显示，标准配置不下载 Blender。
2. 模型服务和 Jev API Key 在「设置 → 模型服务」管理，运行设置只引用已验证配置。神经模式不要求语言模型；可选的语言与 Jev 辅助独立设置调用额度。
3. 连接比赛账户与 PandaData，在「管理合约」按品种或交易所搜索并勾选多个品种。查询实际主力或填写其他交割月份，逐项核对合约、交易所和 tick；目录覆盖不等于每个月份均能交易。
4. 设置交易要求、执行方式与必要额度。逐笔确认只准备计划；自动下单需要确认本轮账户、合约范围和风险。保存设置不会自行开始或恢复已暂停的交易。开始后，完整历史窗口和有效报价就绪才会决策。
5. 「交易」展示合约列表、行情、当前决策与回执；「表现」集中成交和盈亏，「记录」查看运行原因与错误。「生活」中的数字生命可独立体验。
6. 「快速上手」说明环境、账户、合约、行情及回执；高级参数按需展开。空闲时点击抽屉外或按 Escape 收起，保存期间避免误关闭。暂停只停止后续新委托，不撤单、不平仓。

仓位读出（`neural-trade-3`）：方向评分与学习权重来自神经响应，目标资金比例取胜出方向对其他方向/等待阈值的相对优势，再乘以 `1 - 波动读出`。账户动态权益优先读取比赛正式字段 `totalProfit`，兼容 `equity/balance/Balance`。比赛 `contract-spec.margin` 提供多空按金额保证金率和每手保证金，按 `价格 × 乘数 × 保证金率 + 每手保证金` 估算每手占用。容量使用可用资金的 90%（留 10% 应对手续费和价格变化），并受权益按所选品种均分后的 90% 预算、每品种 500 手及用户可选名义上限约束；实际准入以比赛预演结果为准。缺失保证金或资金时等待，不猜测参数。此为工程读出规则，不代表已验证的有效策略。

目标仓位与决策时持仓一同保存，界面展示「当前 → 目标」。每次仅生成差额计划；反向证据先平旧方向，收到成交并无待处理委托后等待新决策。预演前再次核对账户、持仓、资金、可平手数、报价和可选限制；持仓发生变化则放弃旧决策。减仓不受开仓信号过滤阻挡。升级兼容 v2 读出检查点，不重放旧信号。净收益奖励按平仓周期初始账户权益归一化，不再依赖可选名义金额。

历史首次补齐 500 根已完成 K 线，之后复用持久化窗口，按原生 1 或 5 分钟周期从最早缺口或窗口尾部所属交易日期补取，休市时改为每 5 分钟检查。PandaData 接口按交易日期查询，因此最新交易日会有重叠，按时间戳合并去重；不再每轮重取整个初始日期窗口。重启后复用缓存，长期离线导致窗口过旧时重新补齐。果蝇看板与比赛卡片展开区的「获取历史数据」按钮共用同一后台任务，立即返回状态，不阻塞家园。每个合约显示已完成 K 线根数、来源最近成功时间及失败原因，切换合约或周期时不写入旧请求结果。成功获取不等于可交易，仍需通过 500 根完整性及新鲜报价检查。

历史和比赛连接各自持久化冷却状态，手动按钮、自动刷新和页面切换不能绕过。页面区分「比赛接口」和「PandaData」故障，显示重试倒计时。比赛接口限流固定等待 30 秒；其他可重试故障仍按 30、60、120、240、300 秒退避。服务端明确要求更长时间时遵守该时间。限流或授权失效会终止本轮剩余合约请求；其他单合约失败继续处理其他合约，已有缓存与成功时间保留。行情轮询复用短时账户快照，只读同步保留账户身份检查，不再反复执行完整 doctor 自检；交易预演和执行仍使用原有完整校验。

交易决策使用 PandaData 原生 1 或 5 分钟线；3 分钟只用于分析图表的显示聚合，不作为行情请求。合约不自动换月。存在待处理计划或委托时等待；Jev 盯盘运行时不生成果蝇计划。停止建议不撤销已提交委托。

历史行情通过 PandaData MCP 的 `get_future_min` 获取。返回被截断的预览时，程序自动拆分交易日期区间，完整读取各段后统一写入缓存，再校验并取最新 500 根已完成 K 线；不把预览当作完整历史。单日仍被截断或任一分段失败时保留原缓存并报告错误，修复前不绕过历史完整性检查。

手续费、出入金、柜台交易日或完整成交证据缺失时，继续保存实际账户权益和已确认成交，暂停交易奖励结算；缺失数据不按零处理。学习仅发生在读出层，神经连接组冻结。事件回放读取本地记录，不提供旧宿主的历史回测引擎。

状态位于当前 DSH 用户目录下的 `quantskills/fly`。Host 退出等待检查点保存；再次打开恢复记忆、家园及此前启用的交易建议；主动暂停保持暂停，配置不完整时停止建议，重启前的旧信号不重放。源码来源与分发说明见 `packages/quantskills-session/fly-runtime/PROVENANCE.md`。

## 执行方式与本轮授权

JEV 和 AI 交易员均提供「逐笔确认」与「自动下单」。JEV 在运行设置中选择；AI 交易员在「设置 → 运行与额度」中选择。首页显示当前执行方式。JEV 默认逐笔确认，AI 交易员保留自动模式设置，但启用自动下单前必须确认本轮风险。

逐笔确认只准备计划，在「交易计划与回执」核对后点击执行。自动下单先展示本轮账户、合约、额度与运行范围，用户勾选风险说明后，计划才会经 CLI 自动提交。风险说明包括模型判断失误、滑点和未成交、网络延迟、停止线不能保证最大亏损，以及暂停不撤单不平仓。

授权使用版本 `automatic-orders-v1`，连同运行编号和时间记录；不保存进策略模板，不替下一轮启动授权。运行中修改执行方式或交易范围需先暂停。AI 交易员只恢复同一运行编号的有效授权；旧版本无授权运行保持暂停。JEV 与 AI 交易员不同时提交同一账户的策略计划。测试使用模拟 CLI 和隔离账户数据，没有实际下单。

## 自动执行与恢复

- Python 通过经过认证的本机桥接发送决策；比赛凭据与 CLI 执行留在宿主。每个决策编号对应一份计划，执行前先持久化提交状态和请求编号。重复回调返回已有回执，不重复下单。
- 提交前再次核对本轮运行编号、启停状态、账户、合约及额度；在预演期间暂停会取消未提交计划。已经提交的委托继续查询回执，成交仅按柜台明细记账。
- 已知的其他合约委托不阻塞本合约；设置总名义额度时，未完成开仓委托也计入占用，回执核对前保守保留整笔额度。
- 升级前的“生成建议”运行状态不会自动转换成下单，需重新点击开始自动交易。已经明确启动的新版本自动交易可在重启后恢复，手动暂停保持暂停；过时信号和未提交的旧草稿不会补发。
