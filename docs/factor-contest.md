# 第四届因子大赛

侧栏 **比赛 → 第四届因子大赛**。期货模拟赛与因子赛有各自的开关、CLI、账户、专用会话和记录。因子模式默认关闭。

## 首次连接

1. 本机安装 Python 3.10 或更新版本。Windows 和 macOS 使用同一接入流程。
2. 开启 **因子比赛模式 → 登录并连接**，输入 PandaAI 官网账户。应用在自己的数据目录创建 Python 虚拟环境并安装 `pandaai-cli`。
3. 账户登录由本机 Host 按 CLI 的官方登录协议处理；密码不放在命令行、日志或模型上下文中。凭据写入独立 CLI 配置，AI 只收到账号编号和经过过滤的查询结果。
4. 报名、身份资料及赛事协议在官网完成。连接账户不等于已经报名或参赛。
5. 已连接过的账户可点击 **检查连接**。该操作会重新验证身份并停止此前的预算授权；要继续消耗算力，需要重新授权一批研究。

Windows 下，工作目录过深时，CLI 的独立 Python 环境会安装到 `%LOCALAPPDATA%\QuantStudio\factor\` 下的隔离目录，避免 pip 解压依赖时超过路径长度限制。账户凭据、会话和比赛记录仍保存在原工作区数据目录；不同工作区和 CLI 版本不共用 Python 环境。

## AI 研究与预算

**进入 AI 因子助手** 默认继续当前账号主对话；**新建因子专题** 创建独立专题。进入后自动只读巡检，研究由用户主动发起。

告诉 AI 研究方向、回测日期、调仓周期、最多运行次数和算力停止阈值。AI 生成预算卡；在输入框上方 **因子计划** 查看并确认，然后发送“继续研究”或点击 **继续预算内研究**。

- 运行次数为硬上限，每次创建/启动尝试前先持久化占用次数。失败或中断不会自动退还次数并重试。
- 算力是**停止追加的阈值**：每次运行前后核对余额，累计观测到的余额下降；已启动的任务可能越过阈值。平台未提供报价或服务端支出封顶。其他终端的消耗、充值和到账延迟也可能影响余额观测，它不是逐笔账单。
- 一批使用固定日期和周期，不能由模型在启动时覆盖。因子池已锁定周期时，研究必须使用相同周期。
- 可以随时停止追加或关闭模式。**平台已启动的回测和已提交的因子池仍继续运行**，这两个操作不等于取消平台任务。
- 应用重启后，预算不会自动恢复。未明确的回执必须先核对；相同请求不会重复创建或回测。
- 因子代码在平台沙箱执行，本机 CLI 只负责创建和调用。比赛会话没有 Shell、任意 HTTP、外部数据或其它交易工具。

研究记录保留候选定义、工作流/回测编号和结果，供比较 IC、分组收益、换手与样本内外表现。应用不提供无人值守的后台挖掘。

## 因子池与参赛

1. 创建池，选择名称、风格和 1–10 个交易日的统一周期。
2. 在 **可入池工作流** 选择已完成回测、赛事允许入池的工作流。
3. 每次入池、更新、删除和正式提交都会先生成确认卡，界面确认后才发送。AI 没有确认工具。
4. 至少 5 只就绪因子才能正式提交；池容量为 50 只。正式提交锁定周期。
5. 修改/删除时重新核对服务器返回的修改窗口、池状态及因子权限。删除至不足 5 只可能影响当月积分。
6. **积分与成绩** 查询赛事返回的池成绩；工作台可查看当前池、工作流、研究预算和回测记录。

确认计划绑定账号、会话及工作流快照，10 分钟后过期。确认时重新查询；池配置或工作流变化后必须生成新计划。赛事写请求携带固定 `Idempotency-Key`；结果不明时只读查询，不自动重发。只读核对显示目标状态已出现，并不伪造原始服务器回执。

创建工作流的响应完全丢失且没有工作流编号时，必须到官网核对；应用会保留“待核实”并停止追加，无法凭名称猜测成功或自动重建。账户应避免在多个客户端同时操作同一因子池；服务器负责最终窗口、配额和周期校验。

## 数据与更新

数据位于 `<DSH_HOME>/quantskills/factor-contest/`：`auth/config.json` 保存 CLI 凭据，`runtimes/` 保存独立 Python 环境，`state.json` 保存计划、预算及回测记录。默认 `DSH_HOME` 为 `~/.dsh`。不要分享或提交凭据目录。

进入开启的因子页后检查 CLI 最新版本；用户点击安装更新。有有效待确认计划、活动预算或未核实记录时暂缓更新。更新失败保留原运行版本，并要求重新检查连接。
