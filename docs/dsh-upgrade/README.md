## 本轮关闭的阻塞项

1. **插件修改入口统一**：官方管理器负责安装、更新、启停和卸载。旧 dshmarket 不再挂载；实际来源、安装文件与用户配置保留。五类来源、npm 别名、Git/压缩包冒充核心包、未知来源、并发及失败恢复均有验收。事务中断阻止启动；恢复工具使用同一 Profile 锁和启动锁。
2. **完整离线数据核对**：已有一致性备份中的 17,184 个原文件逐一保留；84 个会话新增 v4 文件；两份 SQLite 数据库通过完整性和逐表语义摘要核对。Profile、缓存、附件、交易数据、自建内容与其他文件均在整个代际清单中。真实副本仍不可运行，未调用完整 Host。
3. **实际恢复演练**：先保全整个候选，再恢复旧代际到另一目录。旧版真实解析器读取恢复副本的 84 个会话及 1,223,233 条展开事件，源代际不变。另用无凭据构造样本完成新启动器运行旧核心、迁移后保全与恢复、旧核心再次启动。
4. **四个定制前端回归**：27 个冲突文件逐项处理，114 个测试文件、1,909 项通过。修复布局重新绑定、子任务入口、父子导航回退、思考过程样式、运行状态兼容及损坏的动画资源。真实 Chromium 验证实际构建的会话、附件、草稿、重载和窗口调整。
5. **可选能力与入口**：12 个可选 bundle 默认关闭；通过官方管理器验证启用、重复操作、保存、服务重建后读取、关闭和错误不破坏 Profile。显式启用全部 12 项的隔离 Host 通过完整组合就绪检查。QS 设置中的“更多能力”指向自动化和完整工作台；搜索等扩展配置仍由官方插件页拥有。

## 验收边界与剩余条件

- Windows/macOS/Linux 的新一轮 CI 包含冻结安装、类型、构建、全量回归、上游 UI 行为、实际插件来源、完整样本迁移、新旧核心原生启动、恢复和真实 Chromium。**结果以 [CI 证据](ci-validation.json) 的确定提交为准**，运行中不算通过。
- 账号登录、真实 SSH 服务、麦克风与语音、思考翻译及外部搜索/模型/比赛服务需要独立测试账号、硬件或授权条件。隔离模拟通过不代表这些外部能力已实测；详见 [功能验收矩阵](feature-acceptance.md)。
- 不把旧备份称为“当前日常数据快照”。将来切换实例前仍须取得当时的一致性备份并重新核对；本 PR 不执行该切换。
- 保留 Draft，直到范围内关键外部流程的条件和证据齐全。不会为消除阻塞而导入日常凭据、补跑任务、连接交易账户或更改保护标记。
