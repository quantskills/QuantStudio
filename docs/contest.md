# PandaAI 比赛模式

本页说明：**「巅峰交易者」全国期货模拟赛**。侧栏「比赛」同时提供[第四届因子大赛](factor-contest.md)，两项比赛分别开关和连接。

比赛模式默认关闭。它使用独立的官方 CLI、授权目录和比赛研究会话；普通会话、PandaData 连接、模型配置和能力库沿用原有设置。

## 开始使用

1. 更新代码和依赖后正常重启 QuantStudio，在侧栏 **QUBE → EVO** 下方打开 **比赛**。
2. 开启 **比赛模式**，点击 **连接比赛**。首次连接会在应用数据目录内安装官方 CLI 和交易规则，然后打开 PandaAI 官网授权。
3. 如尚未报名，点击 **赛事报名**，在官网完成报名和身份信息填写。返回应用检查连接。
4. 连接成功后，可查看资金、持仓、当前挂单、委托、成交、排名、每日结算和单品种最新行情。委托、成交默认查询今天，可切换最近记录并翻页。
5. 点击 **进入 AI 交易助手**，默认继续当前赛事账户的主对话；首次进入才创建。**新建专题对话** 用于独立研究，**继续最近对话** 可恢复最近的主对话或专题。旧版未区分类型的会话按最早创建的一条作为默认入口，不改写历史。归档主对话后，下次进入会选择或建立可用主对话。
6. 输入框上方显示账户身份，并自动只读巡检资金、持仓、活动委托和待处理计划。可直接使用 **研究持仓**、**研究品种**、**今日复盘**，或输入自己的需求。**比赛工作台** 返回账户和模式设置。
7. 你选择具体方案后，AI 读取官方执行规范并生成预演。交易确认卡展示实际合约、方向、手数、价格、行情时间、账户和有效期。核对后点击 **确认执行这笔交易**。也可从输入框上方 **比赛计划** 或比赛工作台查看计划及回执。

首版支持 Windows 和 macOS 本机运行，只支持单笔开仓、平仓和撤单。比赛页面需要主机可以访问官方文档及 npm，并可在本机打开浏览器。比赛会话沿用已配置的模型，研究数据通过现有数据库的只读查询或当前会话附件提供。

## 比赛专用对话与隔离

| 层次 | 比赛专用行为 | 普通会话 |
| --- | --- | --- |
| 会话 | 固定赛事、账户和主对话/专题身份，恢复后仍保持绑定 | 保持原会话和历史 |
| 模型与运行框架 | 复用 DSH；只在比赛会话启用原生工具调用和严格工具范围 | 不修改模型、预设和全局工具设置 |
| 提示词 | 巡检、研究、执行准备、复盘分阶段；注入带时间的账户快照 | 不注入比赛提示词、账户快照或交易授权 |
| 常驻技能 | `contest-account-check`、`contest-research-plan`、`contest-daily-review` | 不注册这三项比赛技能 |
| 工具 | 比赛查询、巡检、记录、规范和预演；当前会话附件与缓存数据只读查询 | 维持原工具权限 |
| 执行 | 单笔计划由界面确认；模型没有执行工具 | 不继承比赛授权 |

比赛会话禁止 Shell、任意代码、直接 HTTP、其他交易通道与委派。工具范围和最终调用检查都设置在该会话的作用域内，后续加入的工具也不能绕过。缓存数据查询要求显式 `refresh=false`；需要补充历史行情或更新数据时，到数据库页准备。最新报价不能替代历史数据，缺少数据时应说明缺口。

账户事实每次研究或预演前重新读取。主对话保留用户在该对话确认的约束；专题对话只共享该账户的计划与回执，不自动复制其他会话的聊天记录、偏好或授权。切换账户后，旧比赛会话不能查询或操作新账户。进入会话的自动巡检仅展示只读摘要，不自动发起研究或交易。

## Jev 方案评估

期货比赛专用对话提供 `quantskills_contest_jev_evaluate`，使用 TypeSafe 的 `jev-1.13.0`。现有聊天模型整理带来源和时点的研究依据、用户约束及候选方案，Jev 返回证据充分性、0–3 支持评分和风险判断。概率与置信度是对所给资料的模型判断，不是交易胜率；资料不足时应先补充资料。

普通用户在自己的电脑上安装并启动 QuantStudio，开启期货比赛模式，展开 **Jev 连接配置**，填写自己的 TypeSafe API Key，点击 **测试并保存密钥**。该入口在连接比赛账户前也可使用；测试成功才保存，失败保留原密钥。已有配置可点击 **测试已保存连接**。测试只发送固定的连接检查内容，不发送行情或账户；会调用一次 Jev API。之后连接自己的比赛账户，配置并确认启动盯盘。

密钥通过 Host 凭据服务保存为 `TYPESAFE_API_KEY`（也支持启动进程的同名环境变量；只读来源须在原处修改），页面不回显已保存密钥。每次调用时解析，不写入源码、提示词或工具结果，无需提供文本文件。运行盯盘期间先停止，再替换密钥。工具重新检查绑定账户，向 `https://api.typesafe.ai/v1/systemone` 发送研究依据、资金、持仓与活动委托快照；普通会话和因子比赛不注册此工具。连接失败、超时或无效响应会明确报错，不生成替代结果。这是每位用户独立安装的配置方式，不是多用户共用服务器的账户隔离方案。

工具仅做评估；用户选择方案后，继续通过原有交易预演和界面确认提交。参考：[TypeSafe API](https://docs.typesafe.ai/api)、[模型说明](https://docs.typesafe.ai/models)。


## Jev 持续盯盘与自动计划

点击 **Jev 持续盯盘** 标题可展开或收起整个模块。收起后仍显示运行状态和停止按钮，表单配置保留，后台盯盘不会因此停止。

在比赛工作台的 **Jev 持续盯盘** 选择 **区间回归、趋势回调、突破跟随** 或自己的模板，选择交易品种并填写实际合约后点击 **开始盯盘**。切换内置模板保留当前品种和实际合约；换品种会清除不匹配的合约和历史数据映射。选择模板本身不会启动。首次使用需先完成 Jev 密钥、PandaData 连接和比赛账户验证。

三个内置模板均支持用户选择品种，包含完整的策略文字、对应条件和运行参数：默认 1 手、3 秒采样、30 秒决策、运行 120 分钟、最多 3 个计划、权益回落 1000 元暂停。启动时自动匹配或创建 PandaData 1 分钟行情源。双边手续费及滑点假设为 2 tick（另计实际点差）；换品种时最大点差按 tick 比例换算。这些是可修改的模拟参数，未经收益回测。

新模板默认 **Jev 自主决策**：程序整理已完成 K 线、实时快照、指标、策略文字和持仓，按决策频率交给 Jev 综合判断。区间、趋势、回踩、突破和目标空间/成本的数值条件标为 **Jev 参考**，未达参考阈值不会取消请求，也不会在返回后再次作为硬性入场条件否决模型。账户授权、有效实时行情、允许方向、持仓/手数、最大点差、权益停止线、计划上限和逐笔确认仍由程序执行；历史覆盖与时效也是新开仓的硬性条件。

历史不足时，自主模式仍请求 Jev 判断市场状态、适用性和主要阻碍，同时禁止新开仓；已有持仓的可平动作仍可评估。只有观望可选时，主卡片、分析历史和新事件显示“受限观望”，置信度和动作概率为“不适用”，并说明限制原因；原始模型返回值保留在记录中。有多个候选动作时继续展示真实概率，不能解读为交易胜率。自动历史源暂时连接失败时，可先进入分析模式，并在决策时每隔至少 30 秒重试历史准备；恢复前不开放新开仓。实时行情无效或账户不可用时仍等待或暂停，不调用 Jev。分析会产生 TypeSafe API 用量，不能保证模型提出交易。

选择 **严格规则模式** 可恢复程序先筛选的行为；仅剩观望时不请求 Jev。旧配置未记录模式时沿用严格规则，用户可以显式切换；修改过的策略文字不会自动重写，文字中自行设置的限制仍会送给模型。重新选择内置模板可载入适配两种模式的策略文字；显式选择的模式会保留，保存模板时一同保存。

品种下拉预填螺纹钢、黄金、白银和铝的交易所及最小价格变动；其余品种选择 **其他品种 / 自定义**，填写实际合约、交易所和 tick。支持六个期货交易所的数据代码，但实际可用合约由比赛柜台与 PandaData 权限决定，不自动选择主力或交割月份。预填来源为上期所 2026-01-01 生效的品种细则：[螺纹钢](https://www.shfe.com.cn/regulation/exchangerules/productrules/202512/t20251231_829962.html)、[黄金](https://www.shfe.com.cn/regulation/exchangerules/productrules/202512/t20251231_829960.html)、[白银](https://www.shfe.cn/regulation/exchangerules/productrules/202512/t20251231_829961.html)、[铝](https://www.shfe.cn/regulation/exchangerules/productrules/202512/t20251231_829955.html)。交易所和 tick 可手动核对修改，不是自动更新的合约参数服务。

点击 **＋ 新建模板**，填写名称，选择基于现有模板或从空白创建，再点击 **创建并编辑**。基于模板会复制其完整条件；空白模板仅预填运行参数，需自行填写研究目标和观望、开多、开空、平多、平空五种动作标准，不沿用区间条件。空白策略仍需有效历史行情，并接受账户、持仓、价差与手数校验，具体文字条件由 Jev 判断。

展开 **微调模板** 可修改频率、风控、策略参考资料或行情设置，点击 **保存为我的模板** 保存整套配置。可先不填实际合约保存，启动前必须填写。重开页面后继续选择；同名保存会更新，最多保存 20 个，存于 `<DSH_HOME>/quantskills/contest/jev-templates.json`，不包含密钥。已有实际合约时，选择自己的模板也保留当前品种。**载入上次运行配置** 可恢复此前完整配置。

采样与决策间隔分别设置，均支持 3–86400 秒的整数；新配置默认 3 秒采样、30 秒决策，旧配置保留原采样间隔并补入 30 秒决策间隔。积累至少 8 个不同时间的有效快照后，Jev 在允许的开多、开空、平多、平空和观望中直接选择。分析期间继续采样，同一时间只有一个 Jev 决策请求；分析期间行情失效或存在待处理交易时丢弃该轮结果。决策只在有效采样后触发，实际频率受接口耗时、有效行情和未完成请求影响，不会通过重叠请求追赶设定频率。快照是启动后本机采集的数据，不是历史 K 线；每次决策最多使用最近 60 个快照。空仓时才可建议开仓，有仓时仅允许观望或减仓。符合配置的建议自动生成市价 IOC 冻结计划，仍需在 **交易计划与回执** 中逐笔核对并点击 **确认执行这笔交易**。没有自动执行或自动填写用户确认的接口。

有待确认计划、活动委托或未完成回执时等待；回执不明、账户变化、Jev 错误或权益回落达到停止线时暂停。无效或超过 90 秒的行情不生成计划，重新积累快照。在 **微调模板 → 开仓冷却时间（秒，0 不冷却）** 设置 0–3600 秒，默认 300 秒，从每次生成计划起计算，只限制下一次开仓。已有持仓的平仓判断按决策间隔继续，不受开仓冷却影响。**本次开仓计划上限**只统计生成的开仓计划（取消也占用名额），平仓计划不占名额；达到上限后继续检查账户并评估已有持仓退出，不再新开仓。达到运行时长仍停止。权益停止线相对本次启动时的动态权益计算，触发后不自动清仓，不能保证亏损不超过该数值。置信度也不是交易胜率。

状态区的脉冲动画表示盯盘正在运行，并区分采样、等待行情、Jev 分析和等待计划处理；同时显示最近一次行情检查时间。停止或状态连接中断时动画停止，系统设置为减少动态效果时显示静态指示。柜台的 `2026-09-18 101050` 和 `2026-09-18 10:10:50` 均按北京时间解析。异常提示会区分行情未就绪、合约不符、时间格式、时钟超前、超过 90 秒未更新和无效报价；真正过期的行情仍会等待更新，不放宽有效期。

工作台展示实际行情曲线、采样进度、当前处理阶段、Jev 返回的动作概率和置信度，以及计划生成或未生成的原因。最近 20 轮分析可展开查看输入时间范围、样本数、价格、允许动作、响应耗时和关联计划；运行记录最多保留 100 条。Jev 调用期间展示请求状态，结构化结果返回后才显示概率，不模拟逐字推理内容。

**停止盯盘** 会取消尚未提交的本次自动计划；已提交的委托仍由柜台处理。关闭页面后 Host 继续运行；电脑休眠、服务停止时不能持续采样。服务重启后默认停止，不自动恢复。配置和最近 100 条运行记录存于 `<DSH_HOME>/quantskills/contest/jev-watch.json`，其中不保存密钥。行情样本、账户摘要和用户约束会发至 TypeSafe。

持仓匹配兼容 `ag2612` 与 `AG2612.SHF`；配置了交易所时同时校验后缀，合约月份不同不视为同一持仓。交易所冲突、无法识别的持仓代码或重复持仓记录会暂停。待处理计划结束后立即刷新持仓，避免沿用成交前的空仓缓存。有可平多头时 Jev 只能选观望或平多，有可平空头时只能选观望或平空；平仓建议仍经过置信度、最新行情、账户和人工确认检查。

### 英文输入与专用翻译

界面保留中文原文，发给 Jev 的副本统一为英文。三套内置模板使用精确匹配的预置英文；自定义名称、目标、动作标准及参考资料中的中文由 **Jev 连接配置 → 中文专用翻译模型** 所选的已验证模型翻译。该选择独立于 Auto，不会开启普通模型自动路由。翻译选择保存在 `jev-translation.json`；缓存仅在当前服务内存中，相同原文和模型复用结果，修改内容或重启后重新翻译。翻译模型单独产生用量，不计入 Jev token 汇总。

译文检查 JSON 结构、残留中文和数字，失败时不发送 Jev 请求，也不回退到中文。程序生成的中文检查标签替换为英文定义、检查状态、数值事实及错误码，不需要每轮调用翻译。用户原文不因转换被覆盖。研究评估入口同样转换中文证据与候选方案；翻译只转换语言，决策仍由 Jev 完成。

已保存的旧版趋势模板只有在目标及五种动作文字完全匹配原版时才升级自主说明；用户修改过的文字、参考资料、频率、参数和风控不覆盖。主界面保留行情、动作、候选或计划结果及复核提示；判断依据、调用用量和历史记录按需展开。

历史读取异常按 `阶段/错误码` 区分网络、超时、权限、限流及数据格式。未知失败不再一律指向登录问题；原始上游错误、密钥和连接地址不会显示。

### Jev 调用记录与策略定制

工作台的 **Jev 请求与 token 用量** 每 10 秒读取本机记录，包含盯盘决策、连接测试和研究评估的时间、HTTP 状态、实际返回模型、输入/输出 token、密钥 SHA-256 前 12 位指纹及本地记录 ID。密钥、请求资料及账户内容不写入该记录。汇总累计保留，明细保留最近 200 次，存于 `jev-requests.json`，可导出脱敏 JSON 与 TypeSafe 核对。本地 ID 不是官网请求 ID；未返回 usage 标为未知，旧版本未记录的消耗不能补算。该统计来自 API 响应，不等于 TypeSafe 账单，也不并入普通聊天模型用量。

在 **微调模板** 中可以分别修改研究目标及五种动作的判断标准。支持粘贴或导入最多 12000 字符的 TXT/Markdown 参考资料；链接不会自动读取，资料会发送给 TypeSafe。模板未经收益回测，不提供模型微调或未由 API 支持的 temperature/top_p 参数。每轮分析保留配置版本指纹，并展示返回的 token 用量。

可以设置最少有效快照数（8–60）、允许开仓方向及开仓价差上限（价格单位，0 不限制）。这些条件由程序强制执行，文字资料不能覆盖；限制开仓方向不阻止平掉已有的反向仓位。启用价差限制时，缺少有效买卖报价也不生成开仓计划。生成计划前重新读取账户和行情并校验。

### 历史行情与明确条件

在设置中连接 PandaData 后，内置模板会在启动时自动准备行情，无需手动选择数据集。需要自定义时，在上方选择交易所，在 **微调模板 → 历史行情与策略条件** 中选择 1 或 5 分钟周期；关闭 **启动时自动准备 PandaData 行情** 后，可手动填写带交易所后缀的实际合约（如 `RB2610.SHF`）并创建分钟数据源，或选择已有行情数据集并核对列映射。该操作通过应用已有的 PandaData 连接读取 `get_future_min`，不另存登录凭据。新源启用 `rollingDay`，刷新时将查询标签窗口设为当前北京时间日期至后续 3 天，以覆盖周五夜盘归属周一的情况；历史不会向前无限累积，未来 K 线仍被排除。解析器拒绝将截断预览缓存为完整数据。PandaData 源周期必须与所选 K 线周期一致。

时间无时区时按北京时间解析；PandaData 分钟源按收盘时间处理，旧的自动配置也在读取时纠正，排除尚未结束的条目。手动映射的数据保留用户指定的开盘/收盘时间含义。只接收目标实际合约的有效 OHLC，拒绝重复时间、错误列或过大的数据集；不会用报价伪造历史。允许刷新时每分钟最多检查一次数据缓存，并按原数据源刷新，数据查询不会操作比赛账户。

连续性检查支持已指定交易所的日内休市：SHF、INE、DCE、CZC、GFE 的 10:15–10:30、11:30–13:30，以及 CFE 的 11:30–13:00。休市前最后一根和复市后首根已完成 K 线必须精确衔接；盘中缺失、边界缺失、数据过期仍拦截开仓。未知交易所、隔夜休市、周末或节假日空档不会被自动豁免，检查会列出异常时间戳，等待窗口内积累足够连续数据。时段依据：[上期所及能源中心](https://www.shfe.cn/services/calenderandholidays/tradinghours/)、[中金所](https://www.cffex.com.cn/hs300/)、[大商所](https://www.dce.com.cn/dceg/file/2025-05-29/1748480876704ff80808197162e7128701971994e0a01313.pdf)、[郑商所](https://www.czce.com.cn/cn/uploadfile/2024/01/09/20240109094204181.pdf)、[广期所](https://www.gfex.com.cn/gfex/sspzb/sspz.shtml)。

**区间回归** 默认启用明确区间规则，可修改成本假设、区间回看根数、最小宽度、上下沿触碰次数、边沿比例、回升/回落幅度及目标空间与成本之比。**趋势回调** 默认使用 30 根已完成 K 线、5/20 根快慢均线；要求均线同向且慢均线保持方向，近 3 根 K 线回踩或反弹后恢复，最新报价在快均线 4 tick 内且出现 2 tick 恢复。**突破跟随** 默认以最后一根已完成 K 线确认突破此前 29 根高低点，收盘和最新价均须超出 2 tick，最新价距边界不超过 8 tick。两种新模板默认止损 8 tick、目标 16 tick；它们不使用区间模板的触碰和未突破限制。

预填值是未经回测的示例，换品种时需核对 tick 大小和成本。程序计算历史覆盖与时效、连续窗口和各方向入场条件；休市缺口会使历史连续窗口不满足，需要等待新窗口或调整回看长度。自主模式仅将策略条件作为参考，严格模式中缺失或不满足的策略条件阻止对应开仓。两种模式都保留历史有效性限制，不因历史不足阻止可平持仓退出；止损和目标仅形成待确认平仓建议，不是柜台止损委托。界面区分 **硬性约束** 与 **Jev 参考**，并展示实际模型判断和未生成计划的原因。

输入 Jev 的资料包含策略目标、各动作标准、参考文本、已完成 K 线、实时快照、程序计算的条件及持仓摘要。一次请求独立返回 **市场状态、策略适用性、主要阻碍、动作**，任何一个问题都不依赖看到其他问题的答案。开多和开空按各自条件判断；自主模式以最终动作为候选建议，独立分项判断冲突时提示人工复核；严格模式中冲突仍会阻止开仓计划。低于计划置信度门槛的非观望动作显示为候选建议，不创建可执行计划。计划生成前仍以最新行情和账户再次校验。

界面显示数据来源、覆盖时间、每项条件“满足 / 未满足 / 未知”、Jev 实际返回分类和动作概率。严格模式下程序跳过请求时明确显示 **未请求 Jev**，不伪装成模型观望，也不产生模型 token 消耗；自主模式下诊断请求也记录真实响应与用量。合成场景 API 验证在调用记录中单独标记，不是历史回测，不能证明策略收益。

### 运行中自检失败与重试

**PandaData 已授权，但仍显示“等待行情”**：盯盘的历史 K 线来自 PandaData，实时报价来自比赛柜台的 `quote` 接口，两者独立。先在比赛页「最新行情」查询盯盘所用的同一实际合约，核对最新价与行情时间。柜台明确返回 `ready: false` 时继续等待；没有 `ready` 字段的完整报价按合约、时间和价格校验，不再误判为未就绪。超过 90 秒未更新、未来时间、无效价格或合约不符仍会清空样本并等待恢复，不请求 Jev、不生成计划。可对照[官方行情字段规范](https://www.pandaaiquant.com/openapi/v1/meta/agent-spec)检查接口返回。

行情仍按设定频率采样，完整账户巡检每 30 秒最多一次（生成计划前额外核验），权益停止线的发现可能延迟到下一次巡检。旧版每次采样都执行整套身份和账户查询，3 秒采样易造成接口请求过密。旧版还把 `doctor` 返回的所有失败统一显示为账户自检失败，丢失了限流或网络错误原因。

现在只对明确的限流、超时、网络故障和 429/502/503/504 进行 30、60、120、240、300 秒退避重试；退避时不请求 Jev，清空样本并丢弃过期分析。真实授权失效、账户变化、未知检查失败和不明交易回执仍停止。交易计划创建或提交不会因这一机制自动重试。页面显示错误码与下一次重试时间；历史泛化错误无法据此反推当时的具体原因。

盯盘与交易预演使用相同的实际合约匹配规则：识别大小写差异及交易所后缀，平仓时使用当前持仓返回的合约代码。存在多条同方向匹配持仓、月份或交易所不符、可平手数不足时不会生成计划；不会因规范化合约名称而放宽持仓与预演校验。

## 实际成交价格

交易计划列表及详情会显示实际开仓/平仓成交均价和已记录成交手数。价格仅来自当前账户成交明细，按回执中的委托号以及合约、方向、开平标记匹配，再按手数加权；不会用预演报价、限价或当前持仓成本替代。成交明细随计划保存在 `state.json`，重复回报会去重。连接账户、执行后及回执查询时尝试补齐最近 200 条成交；打开成交历史的旧分页也会补齐对应计划。未执行计划显示未执行，缺少明细显示待核对，可在详情中点击「核对成交价格」。部分记录标明已记录手数，价格补查失败不改变原操作状态，也不会重新下单。

## 开关与交易状态

- 随时可以关闭比赛模式，包括正在安装、登录或等待确认时。关闭会停止比赛调用，使尚未执行的计划失效；普通研究可以继续。
- **关闭比赛模式不会撤销已经提交的委托。** 这些委托继续由赛事柜台处理，可在官网查看，或重新开启并连接后查询。
- 再次开启后需要点击连接验证账户；之前的待确认计划不能继续执行。
- 计划过期或参数变化时需要重新预演。重复点击确认不会创建第二次提交。
- “已排队”“已提交”表示操作处理中；“操作已完成”也不等于全部成交，最终以委托和成交记录为准。
- 丢失回执或应用在提交时退出，计划会标为 **回执待核实**。只能查询柜台回执，不会自动重发。若官网仍无法核实，请先联系赛事支持确认。
- 页面对处理中操作进行有限次数的自动查询，随后可手动查询；Jev 持续盯盘可定时决策并生成计划，提交仍需逐笔确认。

## CLI、更新与数据位置

比赛页自动检查 CLI 更新，安装更新需要点击 **更新 CLI**。有待确认计划、未核实操作或活动委托时会暂缓更新。更新失败保留原运行版本，需要重新检查连接。

比赛数据位于 `<DSH_HOME>/quantskills/contest/`，默认 `DSH_HOME` 为 `~/.dsh`：

- `auth/`：官方 CLI 的独立授权资料，不复用用户全局 CLI 账户。
- `runtimes/<id>/`：独立 CLI 安装和官方交易规则。
- `state.json`：模式开关、账户绑定和计划回执记录。

不要把该目录作为项目文件提交或分享。界面和模型收到的结构化 CLI 响应会过滤凭据及个人身份字段。只有专用比赛会话注册查询、预演工具；执行入口是用户界面的确认操作。

官方资料：[CLI 接入指南](https://www.pandaaiquant.com/openapi/v1/agent-install-guide/cli) · [比赛与报名](https://www.pandaaiquant.com/contest/)
