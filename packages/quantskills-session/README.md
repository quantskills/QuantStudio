# `@deepseek-ai/dsh-quantskills-session`

English | [中文](README.zh.md)

Host-owned exact-version composition for QuantSkills Skill, user Agent, and Agent Team conversations. The service publishes Skill conversation, Agent definition, Agent Team definition, and independent archive methods under `quantSkillsSessions`, and the QuantSkills bundle mounts it beside the immutable installer. Each conversation is an ordinary DSH Session with its own Agent, context, log, title, fork lineage, and archive lifecycle; several Sessions can run independently and the same Skill, user Agent, or Agent Team can own several saved conversations.

The same Remote owns the native-plugin Workspace target. `workspaceStatus` is read-only: it reports an optional preferred registered Workspace and the managed path without creating a directory or registration. `workspaceResolve` accepts a usable preferred Workspace or lazily prepares the managed default on the first QuantSkills Session creation. The managed default is `QuantSkills` under the operating system's resolved Documents directory on Windows and macOS, `${XDG_DOCUMENTS_DIR}/QuantSkills` on Linux, or `~/QuantSkills` when Linux has no documents-directory setting. Resolution is single-flight, treats the normalized path as identity, adopts an existing directory without changing its contents, re-creates a missing directory or registration, and assigns a deterministic numbered title when another path already uses `QuantSkills`. It never uses the DSH process working directory as an implicit fallback. Removing the application plugin leaves the Workspace, Sessions, and user files intact, and existing Sessions retain their recorded Workspace.

`plainSessionCreate` is the Host entry for ordinary QuantSkills conversations and temporary AI helper conversations that do not yet freeze a Skill, Agent, or Agent Team. The caller supplies an explicit `ordinary` or `role-helper` purpose; role drafting and catalog matching share the archive-hidden `role-helper` route. Setup appends one `quantskills/plain-session` ownership event before publication. The `quantSkillsPlainSession` projection restores that purpose after a cold start, so archives, result tools, attachments, and PandaData setup can distinguish product-owned conversations from native DSH Sessions without relying on a title, current route, or browser state. A retry with the same SessionId and purpose is idempotent; another purpose, another QuantSkills composition, or a native existing Session conflicts.

`create` requires a caller-preallocated `SessionId` and one Host-issued installed-version id. It resolves that version from `dsh-quantskills-host` before reserving the identity, then delegates creation to the standard API Proxy. The API Proxy composes registered Host contributors while the Agent and Session remain unpublished. This package installs one scoped provider containing only the exact resolved Skill and appends one required `quantskills/session-bound` event before publication. There is no create-then-bind interval. Publication verification resolves the Skill by its declaration name and separately checks the pinned provider, declaration path, and resource directory; a standard repository whose asset id has the `skill-` prefix therefore retains the exact binding without becoming a second registry name. A retry with the same SessionId and binding is idempotent; an ordinary existing Session or a different binding conflicts.

Fresh creation, cold resume, and API fork all use the same unpublished setup path. Resume and fork fold the binding from the log and re-resolve that exact installed version; they never select the installer's current newest version. A missing, corrupt, or Agent-template version rejects setup before the Agent enters either registry. Catalog Agent templates are imported into user Agent definitions instead of entering this single-Skill path. The session event records `assetId`, `versionId`, exact commit, and validated tree digest, making the scoped model capability reconstructable from durable history.

The `quantSkillsSession` projection folds the once-only binding event and returns `null` for every ordinary or pre-feature Session. `list` unions live and persisted headers, reads the live projection or a cold projection replay, excludes subagent sessions and archived Sessions by default, and returns only bound conversations. Every row projects `idle`, `running`, `failed`, `cancelled`, or `completed` from the live Agent and the last durable Turn ending. `frequent` aggregates those real archive rows by asset id; browser cache and local storage do not create usage history. Passing `includeArchived: true` includes archived rows, and `frequent.limit` is bounded from 1 through 100.

The `quantSkillsResidentSkills` projection folds the immutable Skill or Agent base composition together with later `quantskills/resident-skill-changed` events. `residentSkillAttach` and `residentSkillDetach` serialize changes per Session, operate only on a live QuantSkills Session, and return the authoritative effective list. Attachment resolves an exact installed version before registering its scoped provider and complete declaration as a system-prompt section with `interpolation: "literal"`. Standard Skill template syntax such as `{{task}}`, Mustache conditionals, and unknown double-brace names therefore remain unchanged instead of entering DSH variable parsing. Detachment removes the section and provider after the event is appended. Neither operation creates a user message. Cold resume and fork reconstruct the same effective list and rendering policy, and setup fails before publication if a logged version cannot be resolved. Replacing one asset with another version requires an explicit detach followed by attach.

User Agent definitions are stored by the Host under the DSH home directory and exposed through revisioned `agentList`, `agentCreate`, `agentUpdate`, and `agentDelete` methods. A definition contains a name, a role of at most 128,000 characters, dynamic or fixed orchestration mode, optional model selection, an explicit permission preset, an optional source Agent-template version, and an ordered list of zero through 32 exact installed Skill versions. A zero-Skill definition is a role-only Agent that uses the Session base capabilities. Updates and deletion require the observed revision, duplicate Skills are rejected, and deleting a definition leaves its existing Sessions reconstructable.

`agentSessionCreate` reserves a fresh Session identity, resolves every exact version, and uses the same unpublished API Proxy setup path. Before publication, the setup registers the complete scoped Skill composition, adds the user-defined role and orchestration policy as a system-prompt section, and appends one required `quantskills/agent-session` event containing the complete immutable definition. Agent Sessions have an independent `quantSkillsAgentSession` projection and `agentSessionList` archive method; they never impersonate a single-Skill binding. Cold resume reconstructs the role and every provider from the logged snapshot even after the editable definition is deleted.

Agent Team definitions use a second revisioned Host document and expose `agentTeamList`, `agentTeamCreate`, `agentTeamUpdate`, and `agentTeamDelete`. A saved Team snapshots one Lead Agent and one through eight distinct member Agents, including every Agent role, execution setting, and exact Skill version. Member names are unique lower-kebab-case values other than `lead`; one Agent cannot occupy two roles. Because DSH continuable teammates inherit the Lead runtime, every member must use the Lead model, reasoning setting, and permission preset. Each member independently selects a `fresh` or completed-prefix `fork` context. Updating a source Agent never mutates an existing Team revision, and deleting a Team definition leaves its Session logs reconstructable.

`authoringSessionCreate` creates an independent workspace-write Agent Session and atomically appends `quantskills/authoring-started` with `skill`, `agent`, or `agent-team`. Setup registers tools from that event rather than the Agent display name. Skill and Agent Sessions receive `quantskills_asset_draft`: `list-skills` returns exact bindable versions and `prepare` validates the `quantskills-drafts/` tree through the shared installer rules, resolves runtime requirements, and returns a logged normalized digest. Agent Team Sessions receive `quantskills_team_draft`, whose `list-agents` and `prepare` actions return exact revisions and diagnostics without mutation. Ordinary Agent Sessions receive neither tool. A Client confirmation calls `authoringCommit` with the successful tool call id and expected digest. The Host replays the Tool Result, verifies the authoring kind, rereads and revalidates the draft, performs an idempotent Skill, Agent, or Team commit, and appends one `quantskills/authoring-committed` event. That event restores saved state after cold Client recovery and prevents repeated button clicks from creating duplicates.

Every QuantSkills creation path runs the same Panda preflight before publishing work: ordinary plugin conversation, Skill, Agent, Agent Team, authoring, test, and role-assistance Sessions. The preflight requires authenticated credential replay, a bounded read-only data call, and a bounded execution probe, then resolves one compatible managed Panda runtime and appends `panda/runtime-bound` with its environment id, SDK, Python, and API fingerprint. Hot-plug checks an existing binding instead of silently changing it, and a Team requires one compatible binding across all exact member compositions. The scoped `quantskills_panda_python` tool launches the bound private bootstrap through the standard subprocess and sandbox capabilities. Credentials enter only through stdin; scripts must be inside the Session Workspace or an exact bound asset, and outputs remain inside the Workspace. Native DSH Sessions do not run this preflight or receive the Panda tool.

`agentTeamSessionCreate` freezes the complete Team revision in one required `quantskills/agent-team-session` event before the Lead is published. It installs the Lead role and exact resident Skills, then exposes `activate_team_member` as the only member-creation entry. That tool accepts one declared member name, reserves the child Session identity, and asks the native `ctx.agentTeams` service to start a continuable child with the frozen member role, exact Skill versions, and declared context mode. A member receives one required `quantskills/agent-team-member` event before publication. The generic model-facing `spawn_teammate` tool is absent from the QuantSkills composition, so the model cannot invent undeclared members; native roster, durable mailbox, waiting, interruption, and shared task-DAG tools remain available. Repeated activation of the same member fails and continuation uses `followup_task`.

Team Lead archives have an independent `quantSkillsAgentTeamSession` projection and `agentTeamSessionList` method. Member Sessions remain native subagent children and are excluded from the top-level Team archive list. Cold resume rebuilds the Lead from its logged snapshot; activating a member again rebuilds that child from the member's logged snapshot. Saved-definition revision checks protect edits, while Session creation and retry compare the full frozen Team composition.

`promptFormList` projects optional `qsh-form` metadata only from exact versions that belong to the addressed live Session: current resident Skills, the source Agent template, or the source templates frozen into a Team Lead or member. `promptFormRender` repeats that authorization check, validates task and field values, obtains the real Session attachment list, and renders the approved template with `mustache` in the Host. Its view contains only primitive values, it enables no lambdas or partials, and it disables HTML escaping so the result is plain user text. The Client can submit that text through the ordinary Session prompt path, which records it as a normal user message. An invalid optional form remains listable for diagnostics but cannot render and never blocks installation, natural-language conversation, hot-plug, fork, or cold resume.

`fileAttach` decodes canonical base64 through the generic attachment seam, serializes uploads per Session, enforces the storage service's cumulative Session budget, commits the immutable object, and then appends one `quantskills/file-attached` ownership event containing only its reference, parsing status, and timestamp. UTF-8 text at or below `maxTextAttachmentBytes` (default 1 MiB) is marked `ready`; PDF, DOCX, ODT, PPTX, ODP, RTF, EPUB, XLSX, and ODS files at or below `maxDocumentAttachmentBytes` (default 25 MiB) are admitted for document parsing. `fileList` and `fileRead` enforce Session ownership. Document reads use `officeparser` with OCR and embedded-attachment extraction disabled, then truncate extracted UTF-8 at the text limit. Each QuantSkills Skill or Agent Session receives a scoped `quantskills_read_attachment` tool that exposes only successfully parsed text. Raw upload base64, invalid structures, and guessed binary content never enter the Session log or model request.

`resultPrepare` classifies result paths before they enter the workbench. A regular file already contained by the addressed Session workspace becomes a canonical workspace-relative `ready` result. A legacy path outside that workspace is eligible for archival when the Host proves that it is below `source/output/` of an exact installed QuantSkills version authorized by the Session's Skill, Agent, Team Lead, or Team member composition, or by a successful `skill` tool result durably recorded in that Session. The latter path is accepted only when its rendered resource directory matches an exact installed registry Skill; another installed version that the Session did not load remains unavailable. A different external file is eligible only when the complete durable Session log records a successful mutation Tool call whose pure `presentCall` view names that exact path. The Host copies legacy Skill output into `output/quantskills/<asset>/<commit>/<relative>` and a proven external mutation into `output/quantskills/session-files/<path-digest>/<name>` inside the Session workspace. It returns the archived workspace path and never previews the external source directly. Missing paths, directories, symbolic links, traversal, unrelated installed versions, Assistant-only path mentions, failed mutations, and every other external location return `unavailable` with a user-safe reason.

`resultList` restores result membership from the complete durable Session log instead of the browser's loaded history page. It recognizes safe Assistant inline-code paths and successful mutation paths declared by each Tool's pure `presentCall` view, deduplicates them newest-first, caps the request at 100 candidates, and passes every candidate through `resultPrepare`. Failed calls, read/delete/terminal presentations, malformed historical arguments, unsupported extensions, commands, traversal, and arbitrary prose do not become results.

`resultPreview` reads only a regular file contained by the addressed QuantSkills Session workspace, including legacy Skill output and proven external mutations after `resultPrepare` has archived them there. It never reads an installed-version or other external path directly. It returns bounded UTF-8 text for Markdown, HTML, tabular text, and common source-code and configuration extensions; bounded extracted text from DOCX, ODT, PPTX, ODP, RTF, EPUB, XLSX, and ODS documents; or signature-verified PNG, JPEG, GIF, WebP, and PDF bytes, with `maxResultPreviewBytes` defaulting to 2 MiB. Document extraction uses `officeparser` with OCR, embedded attachment extraction, and raw XML disabled. Unsupported extensions, invalid signatures, invalid UTF-8, parse failures, and known oversize files return an explicit unsupported result instead of inferred content.

Deployments that compose a live-order tool list its exact DSH name in `liveTradingToolNames`. Session setup fails if a configured name is unavailable. Every matching Tool call returns `ask` from the scoped pre-execution policy, so the standard approval service logs a new decision and only `allowed-once` reaches the Tool body; a prior grant cannot authorize a later order. The package does not provide a broker or trading executor, and an empty list enables no live trading.

Every QuantSkills Session also receives one scoped runtime instruction: PandaData is the default data source. A PandaData failure stops the data task and returns a repair action; the model must not substitute AkShare, Yahoo, Tushare, or another source unless the current user explicitly requested that source. Such a request applies only to the current task and does not change the QuantSkills default.

## Model Experience

Indirectly, through the scoped Skill registry and exact literal declaration section for every resident Skill, literal role sections for user Agent, Team Lead, and Team member Sessions, the attachment reader Tool, the PandaData runtime instruction, parameter forms that add ordinary user text, and the live-trading safety section when live-order tools are configured.

#### KV Cache effect

Each effective resident Skill adds its exact declaration literally to the Session-specific request prefix. Attach and detach events therefore change future requests without adding conversation messages; a stable resident set preserves that prefix across turns. A user Agent's logged role adds another stable literal Session-specific section, while changing the editable definition affects only newly created Agent Sessions. Team Leads and members each receive their frozen literal role and exact Skill prefix; the Lead additionally receives the declaration-controlled activation schema and native Team collaboration policy. Attachment and live-trading instructions add stable scoped prefix text. Reading a supported attachment or submitting a rendered parameter form adds ordinary append-only Turn content.

## Known Limitations and Deferred Work

- **Agent templates become editable definitions** — importing a catalog Agent snapshots its approved installed Skill dependencies; later catalog updates do not rewrite the user definition or existing Sessions.
- **Definitions use a Host JSON document** — a sibling file lock serializes writers across Host processes, while an orphaned lock requires operator recovery after verifying that no writer remains.
- **Team members share one permission and workspace runtime** — a Team may combine different roles, Skill sets, and explicit model policies. Each role either follows the Session default model or freezes its own provider, model, and optional reasoning effort; permission preset, working directory, and filesystem remain shared. Write scopes are coordinated by Team tasks rather than isolated sandboxes.
- **Installed versions are retained externally** — this package never upgrades an existing conversation and does not garbage-collect versions; the installer must retain every version referenced by a Session log.
- **Document parsing excludes OCR and embedded attachments** — text PDFs and supported Office containers are readable, while scanned documents and embedded payloads remain durable originals that need a separate explicit Tool.
- **No trading provider ships here** — `liveTradingToolNames` protects explicitly composed DSH tools; the package neither discovers arbitrary trading behavior inside shell/code execution nor submits an order itself.
- **No browser presenter in this package** — it provides typed Host Remotes and projection truth; the QuantSkills Client owns tabs, parallel-run presentation, archive controls, and result drawers.
